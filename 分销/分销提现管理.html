功能说明

一、提现概览

顶部「提现概览」四张统计卡（全量提现数据口径，不受筛选条件影响，随打款结果实时刷新）：

  • 待提现总金额（待提现 + 部分提现剩余金额）：全部「待提现」记录的提现总金额 +「部分提现」记录的剩余未转金额，卡片标题已用括号标注该口径；该金额即财务需充值至微信商户号营销账户、将于次月 1 号批量打款的金额，随批量打款实时减少；
  • 已提现总金额：全部记录已转账金额合计（含「提现成功」全额与「部分提现」的已转部分），即累计已实际转出的提现金额；
  • 代扣税总金额：按已转账金额套用代扣税规则计算的税额合计，即平台已代扣代缴的部分；与「已提现总金额」之差为实际打款到账金额；
  • 提现未完成金额（部分提现剩余 + 提现失败金额）：尚未转出的金额合计，包含两部分——「部分提现」记录的剩余未转金额 + 「提现失败」记录的提现总金额（因实名不一致、风控拦截等原因打款被拒，需重发），示例 ¥5,280.00（部分提现剩余 ¥780.00 + 失败记录 ¥4,500.00）；
  • 数值联动：批量打款 / 单条重新打款成功后，记录状态转为「提现成功」，对应金额由「待提现」「提现未完成」转入「已提现总金额」，并同步累加「代扣税总金额」。

二、提现记录

业务规则：佣金累计达到「最低提现金额」的用户，由系统在每月月底计算生成提现记录，次月 1 号统一批量打款；因此记录存在「待提现 / 部分提现 / 提现成功 / 提现失败」四种状态；余额未达标的佣金不生成记录，仍留存于分销员余额中

  • 状态说明：待提现 系统已计算生成、款项尚未打至分销员；部分提现 按系统配置的单笔最大金额（¥200.00）拆分后仅部分转账成功，仍有剩余金额待继续打款；提现成功 已全额打款至微信零钱；提现失败 打款被拒，需重发；
  • 按月分组：按月份展示提现记录，头部左侧为月份，右侧汇总当月总额、已转 / 剩余金额、转账笔数（已转 / 应转）及待提现 / 部分提现 / 成功 / 失败笔数，并提供「批量打款」按钮；组内按「待提现 → 部分提现 → 提现失败 → 提现成功」排序；
  • 待提现记录：操作列不提供单条打款按钮，仅提示「次月 1 号批量打款」，打款时间显示为「-」；如需提前打款，使用分组头部的「批量打款」；税前佣金超过 ¥20,000 的待提现记录改为红色「超 2 万 · 待人工核定」提示（悬停可看原因），不参与批量打款；
  • 批量打款：每个月份分组头部右侧提供该按钮，蓝色徽标显示该月分组内可打款笔数（待提现 + 部分提现 + 提现失败）；点击后二次确认，弹窗按「待提现 N 笔（金额）/ 部分提现续打 N 笔（剩余金额）/ 失败重发 N 笔（金额）」分项列出，并给出合计金额与本次按系统配置的单笔最大金额需发起的转账笔数；确认即对这些记录一次性批量打款（部分提现记录只打剩余金额），结果逐笔回写为「提现成功」并记录打款时间、清除失败原因；分组内无可打款记录时按钮置灰不可点击；税前佣金超过 ¥20,000 的记录不参与批量打款（徽标计数已排除），确认弹窗中会提示「另有 N 笔需人工核定，暂不计税、不打款」；
  • 独立筛选：支持按分销员姓名、分销员账号、月份区间与状态（可多选，含待提现 / 部分提现 / 成功 / 失败）组合筛选；月份为一个合并输入框，点击调用日期控件选择起始 / 结束月，只填单侧则按单月筛选，倒序自动纠正；
  • 金额构成：每条记录的金额拆分为三项——提现总金额（当月可提现佣金总额，列表主数值）、代扣税金额（按代扣税规则计算）、实际到账金额（提现总金额 − 代扣税金额），后两者相加等于提现总金额；税前佣金超过 ¥20,000 的记录不显示税额与到账金额，改为红色标注「超 2 万 · 待人工核定」；分组头部汇总同口径展示「总额 / 代扣税 / 实际到账」，并单独列出「待人工核定」金额；
  • 转账拆分：每条记录另以三列展示——已转账金额、已转账笔数（已转 / 应转，如 7/11 笔）、剩余转账金额；已转账金额 + 剩余转账金额 = 提现总金额（均为税前口径，笔数按系统配置的单笔最大金额 ¥200 拆分计算）；
  • 身份信息：列表展示分销员姓名、手机号及身份证号，供打款实名核验与税务申报使用；
  • 失败原因：鼠标悬停「提现失败」标签可查看具体失败原因；
  • 重新打款：「提现失败」与「部分提现」的记录均显示该按钮——失败记录整笔重发；部分提现记录仅针对剩余转账金额继续发起打款（弹窗显示已转金额、剩余金额与剩余笔数），打款完成即更新为「提现成功」并记录打款时间；
  • 导出：将当前筛选条件下的全部提现记录导出为 Excel（含提现总金额 / 代扣税金额 / 实际到账金额 / 已转账金额 / 剩余转账金额五列，状态列区分待提现 / 部分提现 / 成功 / 失败，并在表头标注各项合计；税前佣金超 ¥20,000 的记录其代扣税与实际到账列导出为「待人工核定」，表头另附红色说明）

三、转账额度与部分提现

  • 单笔最大金额（系统配置）：打款时单笔转账的上限，本页不直接配置，由运营在「分销等级管理 → 分销配置 → 单笔最大金额」中统一维护（当前配置 ¥200.00）；微信支付商户号「商家转账」的单笔限额默认为 ¥200.00，运营需参照商户号限额配置，且配置金额不能大于商户号限额；超过单笔最大金额的提现记录由系统自动按该金额为上限拆分为多笔转账，逐笔发起、逐笔回写结果；
  • 笔数计算：应转笔数 = 提现总金额 ÷ 单笔最大金额 向上取整，按当前配置 ¥200 计算：¥2,180 → 11 笔（10 笔 ¥200 + 1 笔 ¥180）、¥960 → 5 笔（4 笔 ¥200 + 1 笔 ¥160）；单笔最大金额调整后笔数随之变化；
  • 部分提现：拆分后的多笔转账中部分成功、部分被拒（如收款账户风控、渠道日限额）时，记录状态为「部分提现」；列表三列展示已转账金额、已转账笔数（已转 / 应转）与剩余转账金额，悬停状态标签可查看拆分详情；
  • 继续打款：部分提现记录显示「重新打款」按钮，点击后仅对剩余转账金额继续发起打款（同样按系统配置的单笔最大金额拆分），全部转完即转为「提现成功」并记录打款时间；也可通过分组头部「批量打款」与其他可打款记录一并处理；
  • 示例：提现总金额 ¥2,180 的记录按单笔 ¥200 需转 11 笔，成功 7 笔（¥1,400）后第 8 笔被风控拦截 → 状态「部分提现」，已转账 ¥1,400.00（7/11 笔）、剩余 ¥780.00（4 笔），点「重新打款」继续打剩余 ¥780（4 笔）后转为「提现成功」；
  • 与代扣税关系：转账拆分为打款执行层面的技术拆分，代扣税仍按整笔提现总金额一次性计算（见下节），不影响税额及实际到账金额。

四、代扣税规则（劳务报酬预扣预缴口径）

  • 计税基数：以每条提现记录的税前佣金（提现总金额）为基数，按劳务报酬所得预扣预缴口径计算，代扣税率 20%；
  • 税前佣金 < ¥4,000：应纳税所得额 = 佣金 − 800（每次收入不超过 ¥4,000 时扣除 ¥800 费用）；佣金 ≤ ¥800 时应纳税所得额为 0，代扣税 ¥0.00；
  • 税前佣金 ≥ ¥4,000（且 ≤ ¥20,000）：应纳税所得额 = 佣金 × (1 − 20%)（按 20% 扣除费用）；
  • 代扣税金额 = 应纳税所得额 × 20%；实际到账金额 = 佣金 − 代扣税金额；
  • 税前佣金 > ¥20,000：税率计算方式不同（不再适用上述 20% 单一比例），系统先记账——记录照常生成、金额照常计入统计，但列表金额与状态标红并标注「超 2 万 · 待人工核定」，暂不计税、暂不打款（不参与批量打款，点重新打款也会被拦截），导出明细中「代扣税」「实际到账」两列标注「待人工核定」，待财务按加成征收方式人工核定后再处理；
  • 示例：
    · ¥2,180（<4,000）→ 应纳税所得额 2,180−800 = 1,380 → 代扣税 ¥276.00，到账 ¥1,904.00；
    · ¥800 → 应纳税所得额 0 → 代扣税 ¥0.00，到账 ¥800.00；
    · ¥3,200 → (3,200−800)×20% = ¥480.00，到账 ¥2,720.00；
    · ¥6,000（≥4,000）→ 应纳税所得额 6,000×80% = 4,800 → 代扣税 ¥960.00，到账 ¥5,040.00；
    · ¥23,600（>20,000）→ 暂不计税，金额标红，标注「待人工核定」；
  • 打款口径：系统按实际到账金额打款至分销员微信零钱，代扣税款由平台代扣代缴；批量打款确认弹窗会同时给出「合计金额 / 代扣税合计 / 实际到账合计」；
  • 税务申报：以列表展示的身份证实名信息作为代扣代缴申报依据，导出明细可直接用于财务核对。

五、月度结算与打款流程

  • ① 每月月底（如 28 号）系统计算：系统统计各分销员当月可提现佣金，筛选出累计金额达到「最低提现金额」的用户，按用户生成当月提现记录，状态统一为「待提现」；此时尚未发生实际打款，记录即为本月的待打款清单；
  • ② 财务备款：财务在本页按月份查看「待提现」清单，核对笔数与合计金额无误后，将对应款项从对公账户转入微信商户号运营账户，确保账户余额充足；
  • ③ 次月 1 号系统批量打款：系统于次月 1 号按上月「待提现」记录逐笔批量打款至分销员微信零钱，打款成功的记录状态更新为「提现成功」并写入打款时间；
  • ④ 打款失败处理：打款被拒（如实名不一致、风控拦截）的记录转为「提现失败」并记录失败原因，可点击分组头部「批量打款」（与待提现记录一并提交）或单条「重新打款」重试；
  • 示例：6 月 28 日计算生成 6 月待提现记录 → 财务充值至微信商户号营销账户 → 7 月 1 日系统批量打款 → 记录转为「提现成功」；
