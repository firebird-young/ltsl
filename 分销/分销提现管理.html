功能说明

一、提现概览

四张统计卡为全量口径，不随筛选变化，随打款结果实时刷新：

  • 待提现总金额：待提现记录全额 + 部分提现记录剩余金额，即次月 1 号需备款金额；
  • 已提现总金额：已转账金额合计（含部分提现的已转部分）；
  • 代扣税总金额：按已转账金额计税的合计，已提现总额 − 该项 = 实际打款到账金额；
  • 提现未完成金额：部分提现剩余 + 提现失败金额，示例 ¥5,280.00（¥780.00 + ¥4,500.00）；
  • 打款成功后，金额由「待提现 / 未完成」转入「已提现」，并累加代扣税额。

二、提现记录

佣金达「最低提现金额」的用户由系统每月月底生成提现记录，次月 1 号统一批量打款；未达标佣金留存分销员余额，不生成记录。

  • 状态：待提现 已生成未打款；部分提现 拆笔后仅部分成功，仍有剩余待打；提现成功 已全额打款；提现失败 打款被拒需重发，悬停可看原因；
  • 按月分组：头部汇总当月总额、已转 / 剩余金额、笔数（已转 / 应转）、各状态笔数，右侧为「批量打款」按钮；组内按待提现 → 部分提现 → 失败 → 成功排序；
  • 金额构成：提现总金额 = 代扣税金额 + 实际到账金额；另以三列展示已转账金额、已转账笔数（如 7/11 笔）、剩余转账金额，已转 + 剩余 = 提现总金额（均为税前口径）；
  • 批量打款：徽标为可打款笔数（待提现 + 部分提现 + 失败），确认弹窗分项列出笔数 / 金额、合计金额与需发起的转账笔数；部分提现只打剩余金额，结果逐笔回写为成功并记录时间；无可打款记录时按钮置灰；
  • 单条操作：待提现记录仅提示「次月 1 号批量打款」；失败记录点「重新打款」整笔重发，部分提现记录仅续打剩余金额；
  • 筛选 / 导出：支持姓名、账号、月份区间、状态多选组合筛选；按当前筛选结果导出 Excel（含总额 / 代扣税 / 到账 / 已转 / 剩余五列及各项合计）；
  • 列表展示手机号、身份证号，供打款实名核验与税务申报。

三、转账拆分

  • 单笔最大金额：打款单笔上限，本页不配置，由运营在「分销等级管理 → 分销配置 → 单笔最大金额」维护（当前 ¥200.00），不得大于微信商户号「商家转账」的单笔限额（默认 ¥200.00）；
  • 拆分：超过该金额的记录自动拆为多笔转账逐笔回写；应转笔数 = 提现总金额 ÷ 单笔最大金额 向上取整，如 ¥2,180 → 11 笔、¥960 → 5 笔；
  • 部分提现：多笔中部分被拒（风控、日限额）时为「部分提现」；示例 ¥2,180 按 ¥200 需转 11 笔，成功 7 笔（¥1,400）→ 已转 7/11 笔、剩余 ¥780.00（4 笔），续打后转成功；
  • 拆分为打款执行层面的技术拆分，代扣税仍按整笔提现总金额计算，不影响税额与到账金额。

四、代扣税规则（税率 20%）

  • 税前佣金 < ¥4,000：应纳税所得额 = 佣金 − 800（≤ ¥800 时为 0）；¥4,000 ~ ¥20,000：应纳税所得额 = 佣金 × 80%；
  • 代扣税 = 应纳税所得额 × 20%，实际到账 = 佣金 − 代扣税；示例：¥2,180 → 税 ¥276.00；¥800 → ¥0.00；¥6,000 → 税 ¥960.00；
  • 税前佣金 > ¥20,000：税率计算方式不同，系统先记账——金额与状态标红标注「超 2 万 · 待人工核定」，暂不计税、暂不打款（批量打款与重新打款均拦截），导出对应列标注待核定，待财务人工核定后处理；
  • 系统按实际到账金额打款，税款由平台代扣代缴；确认弹窗同步给出合计金额 / 代扣税 / 实际到账。

五、月度结算流程

  • ① 月底计算：按「最低提现金额」生成当月待提现记录；② 财务备款：核对清单后将款项转入微信商户号运营账户；③ 次月 1 号打款：批量打款至微信零钱，成功记录写入打款时间；④ 失败处理：转「提现失败」并记录原因，可批量或单条重试；
  • 示例：6/28 生成待提现 → 财务备款 → 7/1 批量打款 → 转「提现成功」。
